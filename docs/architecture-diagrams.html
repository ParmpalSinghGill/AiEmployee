System Design · ai_employee

AI Employee Framework

A provider-independent multi-agent system. A goal enters as text; a LangGraph pipeline decomposes it, delegates each step to a specialized agent, verifies the output, and folds the result back into memory. No business logic ever imports an LLM SDK.

29 agents 7 providers 23 tools 3 orchestrators 7 memory namespaces

01 Layered structure

Dependencies point downward only. The Brain interface is the choke point every model call passes through — swapping LLM_PROVIDER changes the entire system's reasoning engine without touching a line above it.

02 The execution graph

The main Orchestrator is a LangGraph state machine over a typed EmployeeState. The interesting part is not the happy path — it is the two ways a run leaves the loop early, and the state that survives when it does.

03 Inside a step: the agent loop

Each execute node hands one step to a ToolUsingAgent — a ReAct loop bounded on four separate axes, because an unbounded tool loop is the default failure mode of this architecture.

Component inventory

LayerModuleResponsibility
Brain brains/base.py One interface: chat, stream, complete, structured_output, embed. Wrapped by MeteredBrain always, and by ExplainBrain when EXPLAIN_TRACE is on.
Agents agents/specs.py 29 roles, most declared as data — system prompt, allowed tools, iteration cap — plus a few bespoke classes in agents/custom.py. ToolUsingAgent supplies the shared ReAct machinery.
Tools tools/builtins/ Filesystem, Python & shell exec, HTTP, search, CSV/JSON, plus a research suite (HF, arXiv, GitHub, Kaggle, Roboflow) and the resource downloader. approval_key marks the mutating ones.
Memory memory/resilient.py pgvector or in-process vectors behind one VectorStore API, across seven namespaces. auto degrades to in-memory on DB failure; use pgvector explicitly to fail loud.
Knowledge knowledge/rag.py Loaders → chunker → embeddings → the knowledge namespace. Retrieval grounds answers with citations.
Verification verification/ Verifier reviews each step against its success criteria; audit_resources separately checks that claimed downloads exist on disk.
Persistence observability/store.py Sessions, task records, memory snapshots and the usage ledger on disk, so a restart can resume interrupted runs.

04 Runtime path of one task

The console never blocks on a run. TaskManager launches the pipeline in its own asyncio task with a task_id bound to the logging context; the SPA polls a snapshot cursor. That contextvar is the entire mechanism by which deeply nested log events find the right browser tab.

05 Invariants the design rests on

These are not style preferences — each one is load-bearing, and violating it breaks a property the rest of the architecture assumes.

no SDK above the Brain Business logic never imports an LLM SDK. Provider knowledge lives in brains/providers/ and brains/factory.py, nowhere else.
config, not code LLM_PROVIDER is the single switch. No module branches on provider identity to change behavior.
offline is a first-class mode mock brain + mock embeddings + in-memory store must run the full pipeline with no network and no database. The test suite enforces it.
async all the way down Public APIs are async; nothing blocks the event loop, because the task runner shares it with the API process.
sensitive ops are gated A tool with an approval_key in approval_required cannot execute without approved=True — the gate is in the registry, not in any agent's prompt.
